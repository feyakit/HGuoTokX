## 一、P0

### #3 播放器无可用暂停、进度条点了没反应

**现象**（报告）：点 ⏸（145,3000）两次时间照走、图标一直是 ⏸；点画面中央只切控制层显隐；点进度条（1000,3050）打开系统最近任务；沿进度条拖动无反应；补偿点按后时间从 0:59 回跳到 0:20。

**根因**（代码层三条，全部实测过）：

1. **中央轻点按设计只切「净屏」**，暂停要靠双击——而 3.0.0 的提示里从没说过，用户根本摸不到。位置见 `onUp()` 的 `mode === "idle"` 分支：首击 `setClean(!clean)`，第二击才 `videoRef.toggle()`。
2. **⏸ 按钮本身是好的**：`onClick → videoRef.toggle() → usePlaybackActivity.pause() → video.pause()` 通路完整，`onPause → setPaused(true)` 也会让图标翻成 ▶（L2 打桩实测见下表）。设备上「点了没反应／时间回跳」是 **#2 点按偏移**把落点挪到了进度条上造成的（0:59 → 0:20 正是一次 seek）。
3. **控制区离屏幕底边太近**：底栏 inset=0 时整块只离底 28px，进度条落在 52–80px 区间，正好压在 Android 手势条上（报告「点进度条打开了最近任务」）。

**改法**：

- `onUp()` 单击改为 **暂停/继续**（180ms 判定窗，双击才净屏，避免双击时先闪一下暂停）；双击仍保留净屏。
- ⏸ 按钮 40 → 44px，补 `onPointerUp` 也 `stopPropagation`，`aria-pressed` 跟播放状态绑定。
- 底部控制块整体上移 16px（`bottomInset + 28` → `+ 44`），进度条底沿从约 52px 抬到约 68px，离开系统手势区。
- 进度条 hitTest 本来就是独立的（`onBarDown/Move/Up` 自己 `stopPropagation` + `setPointerCapture`，不与切集手势共用），未改；拖动/点击都走 `videoRef.seek()`。
- 集数条补「跟随当前集滚动」（切到第 13 集时当前 chip 常在视口外，看起来像没选中）。

**状态** ⚠（L2 已验通路，真机待复测）

| 验的什么 | 怎么验 | 结果 |
|---|---|---|
| ⏸ 是否真调 `video.pause()` | 打桩 `HTMLMediaElement.pause/play` + `paused` getter，真 touch 点按钮 | `pause()` 被调用、`paused` 变 true |
| 图标是否跟播放状态双向同步 | 派发真实 `pause` 事件 | `aria-label` 从「暂停」→「播放」 |
| 再点一次是否恢复播放 | 同一次会话 | `play()` 被调用、回到播放态 |
| 中央轻点是否暂停 | `Input.dispatchTouchEvent` 点画面中央 | `pause()` 被调用，**控制层没有消失** |
| 按钮/进度条位置 | DOM | 按钮 y 638–682（屏高 792），进度条 696–724，底沿距屏底 68px |

### #7 轮播：滑动/点圆点/自动轮换全无效

**现象**：hero 固定「神瞳觉醒 第一季」，横滑两次不动、点第 2 个圆点不动、3 分钟无自动轮换。

**根因**（三条独立的）：

1. **圆点热区只有 3px 高**（`.hg-spotlight-bar { height:3px; width:18px }`）。视觉上就是 3×18 的细条，手指按 3px 高的东西基本按不中——按不中自然「点了没反应」。这是「圆点成了纯装饰」的直接原因。
2. **自动轮换的定时器在重构时整个丢了**：3.0.0 的 `Home.tsx` 里没有任何 `setInterval`，圆点只是索引指示器。
3. 横滑手势 W18 已补（本轮保留、未改）。

**改法**：

- 圆点视觉不变，用 `::after` 把热区上下各扩 12px（3px → 27px 可点高度）。L2 实测：圆点上下 ±10px、右侧 +12px 的点按都命中按钮本身。
- 恢复自动轮换：6s 一页，只在「推荐」分栏可见 + 页面在前台时走；手动切页（圆点/横滑）会把定时器重置，不会刚点完就被换走。
- 确认 `setHeroIndex` **真的驱动 hero 切换**（不是只改高亮）：`hero = heroes[safeHeroIdx]` 是数据驱动的，L2 点第 3 个圆点后标题从「网调我的冰山妈妈」变为「少妇白洁」，`data-on` 同步。
- W18 的 `heroTouch` 手势原样保留，L2 回归：左滑 130px → 索引 0→1、hero 换片。

**状态** ✅

## 二、P0（报告最严重的系统性问题）

### #2 点按落点与响应不一致（越靠下偏得越多，约 140px）

**结论：代码层没有找到坐标换算错误，不建议在本轮改代码。**

代码审计（逐项过）：

| 查什么 | 结果 |
|---|---|
| `index.html` viewport | `width=device-width, initial-scale=1.0, viewport-fit=cover`，没有 `maximum-scale` / 固定宽度 |
| `tauri.conf.json` windows | 1200×780 是桌面窗口配置，Android 由生成的工程全屏，不影响手机 |
| `html/body/#root` 高度 | `height:100%; height:100dvh; overflow:hidden`，无 JS 钉死高度（`main.tsx` 里已注释掉旧做法） |
| 有没有把 `screen.height` / `innerHeight` 用于命中换算 | **没有**。只有两处：`isLandscape` 判定（`innerWidth > innerHeight`）和诊断日志 |
| 有没有 `transform: scale()` 缩放整页 | 没有。只有视频舞台的 `zoom`，且限制在视频容器内 |
| 手势 handler 是否自己换算坐标 | 没有，全部用 `clientX/clientY` 直接与 DOM 比对 |

偏移量与报告吻合：`140 / 3168 ≈ 4.4%`，正是「内容视口 1440×3028 被拉伸到 1440×3168」这种**覆盖面分辨率下 WebView 视口 ≠ 触摸空间**的比例错位，属系统/容器层，不是应用层。

**改法（只加诊断，不动坐标）**：`src/layoutDiagnostics.ts` 原来只在 iOS 采集，现在安卓也采。装上后 `debug.log` / 播放诊断里会同时打出 `screen`（物理）、`window.innerHeight`（CSS）、`visualViewport`、`100vh` / `100dvh` 探针实测值、`#root` 实际矩形 —— 真机上这四组数一对，就能确定是覆盖分辨率还是应用换算。

**状态** ⚠ **需小米9 真机（不设 `wm size`）复核**

- 若小米9 上落点准确 → 结论是 phone2k 覆盖分辨率所致，报告里要写明「模拟器覆盖分辨率的触摸映射问题，非应用 bug」。
- 若小米9 上也偏 → 拿上面四组数回来再定位（那时才动代码）。

## 三、P1

### #5 字幕压住时间读数（字幕烧在画面里）

**现象**：片源自带的大号白字字幕盖住左下 `0:26 / 4:58`，时间看不全。

**根因**：字幕是**烧进视频画面**的，不是独立字幕轨——所谓「字幕层与控制栏分层」在客户端做不到（没有可控制的那一层）。3.0.0 只在控件层加了一条 168px 的渐变，但读数本身是裸字，字幕正压上去就糊。

**改法**（报告给的第二个方案「时间/进度条加半透明底衬」）：

- 新 `.hg-video-time`：`rgba(0,0,0,.46)` 底 + 6px 背景模糊 + 1px 内描边 + 12px/600 白字，把「当前 / 总时长」做成底衬胶囊。
- 底部渐变压暗从 `.6` 提到 `.72`、高度 168 → 196，覆盖到集数条下沿。

**状态** ⚠（L2 量到 `.hg-video-time` 92.3×26、底衬生效；字幕实际叠压只能在真机看片时确认）

### #12 详情页 点赞/收藏/评论 三组数字被右缘切掉

**现象**：「点赞 18.5 万 · 收藏 10.9 万 · 评论」——「评论」只剩半截字，评论数完全看不见。

**根因**：该行 `flex-wrap: nowrap` + `overflow-x: auto`，内容超宽时被右缘硬切；横向滚动没有任何视觉提示，用户只会读到「字被切了」。

**改法**：改成 `flex-wrap: wrap`，每组「标签+数字」是一个 `nowrap` 单元，**只在组与组之间换行**，永远不会拆开标签和数字、永远不会切字。

**状态** ⚠ 已消除裁切，但**单行在 360 CSS 宽下放不下**，实测数据：

| 项 | 值 |
|---|---|
| 详情头列宽（`poster 126 + gap 12`，行宽 304） | 166px |
| 「点赞 18.2万 · 收藏 10.7万 · 评论 738」在 11px 下需要的宽度 | ≈194px |
| 结果 | 折成 2 行（点赞·收藏 / 评论），三组数字全可见 |

要真的单行，只有两条路，都要**产品拍板**：① 统计字号降到 ~9.5px（可读性不足）；② 让该行跨到海报下方通栏（改版式）。本轮按「不发明设计」停在这里。

### #16 分类页末行被底部导航遮

**根因**（两条，只有一条是真 bug）：

1. 列表底部留白其实已经够：360×792 实测滚到底时最后一格 bottom=615.5，导航 top=682，**余量 66.5px**，末行完整可见（`padding-bottom: 110 + sab`）。
2. 真问题是**无限加载没有收尾**：报告里「没有到底部、没有『没有更多』」——用户永远不知道还有没有，于是把滚动过程中从浮层下经过的行当成「被遮」。

**改法**：分类页与首页「为你推荐」在 `done` 时给出 `已经到底了 · 共 N 部` 收尾行（`.hg-list-end`）。

**状态** ✅（L2：收尾行 bottom=658 < 导航 top=682，在导航上方完整可见）

> 说明：滚动过程中某一行从悬浮底栏下方经过，是悬浮底栏的常态，不按缺陷处理（与既有验收口径一致）。要把导航改成不压内容的固定底栏，属于「去胶囊」那次设计改动，不在本轮。

### #17 点「全屏」不横屏、视频反而暂停

**现象**：点播放器底部「⛶ 全屏」后画面仍是竖屏，时间照走。

**根因（硬结论）**：**安卓端根本没有横屏能力。**

- 前端 `enterFs(true)` 会调 `invoke("set_orientation", { landscape: true })`；
- 后端 `src-tauri/src/api.rs:456` 的 `set_orientation` **只对 iOS 有实现**，`#[cfg(not(target_os = "ios"))]` 分支是空操作；
- `screen.orientation.lock("landscape")` 在 Android WebView 里要求页面处于 Fullscreen API 全屏，Tauri 的 WebView 拿不到，`catch` 把 reject 吞掉；
- 剩下的 CSS 旋转兜底只对**横版视频**生效（`rotated = fs && videoSize.w > videoSize.h`），而短剧是 9:16 竖版 → 什么都不转。
- 所以「全屏」这个按钮承诺了一个安卓永远做不到的行为。

**改法**：按报告建议与项目既有约定（`hguox-mobile-shell` 规则 17：「竖屏短剧的播放器不要放全屏/横屏入口，做不了就删」）**删掉该按钮**（连带删掉只为它引入的 `IExpand` 引用）。`fs` 沉浸层本身保留——物理横置手机时仍会自动进入全屏（`orientationchange` 分支），这条通路是有效的。

**状态** ✅（按钮已移除；「真横屏」若要恢复，必须写 JNI 调 `Activity.setRequestedOrientation` + 出包 + 真机验，属独立任务）
