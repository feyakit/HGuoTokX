# 已知问题（暂时不修的，附原因与再修时机）

> 口径：**能修的都已经修了**，这里只放「知道有问题、但这一轮判断不该硬修」的。
> 每条写清四件事：现象 / 根因 / 为何暂时不修 / 何时再修。
> 最后更新：2026-11-17

## 1. `scripts/test-ios-ui.mjs` 仍然 8/8 场景红

**现象**：8 个视口场景全部失败。最近一次失败点在「我的」页拿 `.ios-score-badge`、
以及桌面场景找首页卡片上的评分角标。

**根因**：这个用例写的是**重设计之前**的那套视觉语言，代码已经整体换过：
- 底栏从「不透明白玻璃 + 选中深墨字 + 浅色胶囊」改成「半透明玻璃 + 白字 + 无胶囊」；
- 卡片从 `ios-*`（`ios-poster-art`、`ios-score-badge`）换成 `shelf.css` 的 `hg-poster`，首页/分类网格不再画评分角标；
- 榜单类型从 `SegmentedControl`（`role=group` + 滑动指示块）换成胶囊 tab（`role=tablist`）；
- 底栏去掉了「搜索」项；桌面侧栏只有 首页/分类/我的（另有排行榜、设置）。

**这一轮已经修的**（都是选择器/前置条件，断言一条没放宽）：
使用协议闸门补种、底栏标签表、桌面/移动分开的导航标签、搜索入口改到品牌行图标、
榜单改成 tablist + `aria-selected`、榜单行 `.ios-rank-row` → `.hg-rank-row`、底栏选中字色改白。

**为何暂时不修**：剩下的红全是**设计口径**（评分角标位置、底栏材质、卡片几何），
不是改两行选择器能收的；要么把断言改成新设计，要么把用例重写一遍，
而它同时还在断言卡片尺寸/角标位置这些已经迁到 `shelf.css` 的东西。
半改会得到一个「看起来绿、其实什么都没验」的用例，比红着更糟。

**何时再修**：等 `shelf.css` 这套原语定稿（首页/分类/榜单/我的 四屏不再改结构）后，
按新原语重写一版 `test-ios-ui`：只保留「结构 + 可读性 + 交互」三类断言，去掉像素级材质断言。

## 2. `scripts/test-playback.mjs` 本地默认跑不起来

**现象**：`npx playwright install` 提示缺浏览器，用例 0 passed / 1 failed。

**根因**：它用 `playwright-core` 的 `chromium.launch()`，没有 `executablePath` 就找 Playwright 自带的浏览器；
本机（容器）只装了 `/opt/hermes/tools/chromium-1208/...`。

**为何暂时不修**：不是代码问题，是本机没装 Playwright 的浏览器包；
CI 里用 `pnpm exec playwright install` 就正常。

**本地怎么跑**：`node scripts/test-playback.mjs --browser-executable=/opt/hermes/tools/chromium-1208/chrome-linux/chrome`
（本轮没跑，因为它还会起本地媒体服务，属于独立验证）。

**何时再修**：把 `--browser-executable` 缺省值改成读 `BROWSER_EXECUTABLE` 环境变量（其它用例都这么写），
下次动播放相关代码时顺手改。

## 3. `scripts/test-round-review.mjs` 只在 GitHub Actions 里跑

**现象**：本地跑直接报 `Run this review only in GitHub Actions.`

**根因**：它是 CI 里的聚合回归（要 clone 基线 `455f3ab` 再跑一整套），本地跑没有意义。

**这一轮的处理**：改成打印 `SKIP: …` 并 `exit 0`（CI 里行为不变），
否则「本地把所有 test-* 跑一遍」永远会多一条红，掩盖真正的问题。

**何时再修**：不需要；如果以后要本地复现，给它加一个 `--baseline <sha>` 参数即可。

## 4. iOS 图标矢量源不在仓库

**现象**：`scripts/test-ios-icons.mjs` 以前直接 ENOENT。

**根因**：上游同步（`1d7b825`）之后仓库只带生成好的 PNG，没有 `src-tauri/icons/ios/source.svg`；
`scripts/generate-ios-icons.mjs` 自己已经写了「缺源就跳过并沿用已跟踪 PNG」。

**这一轮的处理**：用例改成「有源就校验源、没源就打 SKIP 并继续校验 18 个槽位的 PNG + 构建钩子」，
与构建脚本行为对齐。

**何时再修**：如果决定把矢量源重新入库，再把那两条断言无条件打开。

## 5. 分类页二级 chips 的取数成本

**现象**：分类页第一次激活时会打 3 个 `/api/videos?size=30`（约 90 条）只为统计 tags 频次取前 8。

**根因**：站点接口没有「题材 chips」这种聚合，`api.tags` 返回的是分类而不是二级 chips，
所以当年用「拉 3 页数频次」的办法，不硬编码。

**这一轮的处理**：从「页面一挂载就打」改成「跟着 `active` 走、且只打一次」——
隐藏的 tab 不再白打 90 条，切回来也不再重复。

**为何不彻底换掉**：要换得等接口给出 chips 聚合，前端自己算频次换不掉。

**何时再修**：上游提供 chips/tags 聚合接口时，删掉这段统计逻辑。
